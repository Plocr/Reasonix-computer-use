## 2026-07-31 · QQ音乐播放许嵩的歌 — 双击失效与任务循环

### 任务背景

用户指令：`/computer-use:run 打开qq音乐，并播放许嵩的歌`。

### 问题现象

1. **双击不生效**：Agent 先用了不存在的动作名 `dblClick`（报 `unknown_action_type`），
   之后改用两次 `click` 模拟双击，歌曲列表项始终没有打开/播放。
2. **任务陷入循环**：最终任务实际已播放成功（用户确认），但 Agent 无法确认播放状态，
   反复执行"点击→观察→无变化→再点击"，共调用工具 **30 次**，耗时约 10 分钟，
   且没有正确结束任务。

### 根因分析

| 现象 | 根因 |
|---|---|
| 双击被识别成两次单击 | 插件 `mouse_click` 时序是"机器级"：按下→抬起仅 **20ms**，多击间隔仅 **50ms**。真人双击按下保持约 60~100ms、两击间隔约 150~300ms。QQ 音乐等自绘 UI（DirectUI/CEF）对过快的事件不稳定，把机器级双击当成两次单击 |
| 任务无法确认完成而循环 | QQ 音乐底部播放器栏不向 UIA 快照暴露曲目名/播放状态（快照里只有旧曲目信息，点击后无任何元素变化），Agent 缺少"播放成功"的证据，于是不断重试；同时 SKILL.md 没有"最大重试次数"和"完成判定"的约束 |

### 修复内容

1. **`reasonix_computer_use/platform/windows.py` → `mouse_click`**：人性化时序
   - 按下保持：20ms → **60ms**（`PRESS_HOLD = 0.06`）
   - 多击间隔：50ms → **200ms**（`CLICK_GAP = 0.20`）
   - 仍在 Windows 双击阈值（`GetDoubleClickTime` 默认 500ms）内，系统仍识别为双击，
     但给了应用足够的处理时间。
2. **`reasonix_computer_use/tools/screen_interactor.py` → `double_click` 分支**：
   执行双击后自动 `time.sleep(0.3)`，给应用反应时间（弹出面板/开始播放），
   避免 Agent 紧接着观察时 UI 尚未更新。
3. **`skills/computer-use/SKILL.md`**：
   - 明确"双击必须用 `double_click` 动作，严禁用两次 `click` 模拟"；
   - 新增「完成判定与退出（防循环）」章节：
     - 同一步骤最多重试 **2 次**，之后停止并汇报；
     - 快照看不到状态变化时改用替代证据（`screenshot` 截图、播放提示音、窗口标题）；
     - 目标动作已执行且无"未生效"的反向证据 → 判定完成并立即结束。

### 验证

- `py_compile` 语法检查通过；
- 单元断言（mock `time.sleep` 收集时序）：单击 `[0.03, 0.06]`，双击 `[0.03, 0.06, 0.20, 0.06]`，
  鼠标事件数 2/4 正确；
- 完整测试套件：**58 passed, 193 skipped**（跳过项为旧架构 legacy 测试），无回归。

### 实测确认（2026-07-31 晚 · 用户复测）

修复后用户重新执行 `/computer-use:run 打开qq音乐，并播放许嵩的歌`，
**可以正常播放** ✅。双击生效、任务完成，未再出现之前的循环重试问题。
（本次实测确认了"人性化点击节奏"和"防循环规则"两个修复方向都有效。）

### 经验教训（可复用）

1. **自动化点击要模仿人类节奏**：按下保持 60ms+、双击间隔 150~300ms。机器级速度在
   自绘 UI（QQ音乐、CEF、游戏客户端）上不可靠。
2. **Agent 需要"任务完成判定"规则**：UIA 快照不是万能的——很多应用的关键状态
   （播放器曲目、视频进度等）不暴露给无障碍树。规则里必须有"替代证据"和"最大重试次数"，
   否则 Agent 会陷入无限重试循环。
3. **动作名必须写进技能文档并强调**：Agent 会发明不存在的动作名（如 `dblClick`），
   正确动作是 `double_click`。技能文档要显式列出"常见错误动作名"。
